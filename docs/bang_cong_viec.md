# 📊 Bảng Phân Công Nhiệm Vụ & Quản Lý Tiến Độ (Agile/Scrum)

Dự án BrewLite được triển khai theo mô hình **Agile/Scrum**, chia làm các Sprint nhỏ để phát triển tăng dần (Incremental Development). Quá trình phát triển được chia làm 2 giai đoạn cốt lõi: **Giai đoạn 1 (Phát triển độc lập & Component Testing)** và **Giai đoạn 2 (Tích hợp hệ thống - System Integration & Validation)**.

Dưới đây là chi tiết công việc của nhóm (6 thành viên) qua từng giai đoạn:

| STT | Thành viên (Vai trò) | Giai đoạn 1: Phát triển Độc lập (Sprints 1-2) | Giai đoạn 2: Tích hợp Hệ thống & Khắc phục (Sprint 3) |
| :--- | :--- | :--- | :--- |
| 1 | **Lai Minh Hậu**<br>*(Leader)* | - Thu thập & Đặc tả yêu cầu (Requirements Specification).<br>- Viết User Stories & Acceptance Criteria.<br>- Thiết lập kiến trúc Monorepo (Next.js & NestJS). | - Thực thi Quản lý cấu hình (Configuration Management) bằng cách đóng gói Docker Compose.<br>- Khắc phục lỗi môi trường: Bổ sung OpenSSL cho Alpine image để ORM kết nối Database thành công.<br>- Tự động hóa quá trình Migration & Seeding dữ liệu. |
| 2 | **Lê Duy Hiếu**<br>*(Frontend Developer)* | - Phát triển giao diện (UI) Menu và trang Chi tiết sản phẩm.<br>- Áp dụng **Prototyping**: Sử dụng Mock Data (dữ liệu giả) để đảm bảo tiến độ xây dựng UI không bị phụ thuộc vào Backend. | - **Refactoring:** Tái cấu trúc toàn bộ logic lấy dữ liệu (Data Fetching). Gỡ bỏ Mock Data để tích hợp API `GET /products` thực tế.<br>- Bổ sung xử lý ngoại lệ (Exception Handling): Thêm trạng thái Loading và Empty State khi API phản hồi chậm hoặc lỗi. |
| 3 | **Nguyễn Đình Hùng**<br>*(Frontend Developer)* | - Xây dựng logic Quản lý trạng thái (State Management) cho Giỏ hàng bằng Zustand.<br>- Thiết kế UI màn hình Xác nhận đơn & Thanh toán. | - **Vá lỗi bảo mật & Memory:** Viết hàm tự động dọn dẹp LocalStorage cho khách vãng lai sau thanh toán (đảm bảo Non-functional requirement về Privacy).<br>- Khắc phục lỗi vòng lặp render vô hạn (Infinite Render) khi tính tổng tiền.<br>- Tích hợp Token JWT vào HTTP Header. |
| 4 | **Thái Hiển Long**<br>*(Backend Developer)* | - Thiết kế Database Schema cho `Product` & `User`.<br>- Phát triển API `GET /products`.<br>- Xây dựng module Authentication (Băm mật khẩu, cấp phát JWT). | - Các API đã vượt qua Component Testing xuất sắc từ Giai đoạn 1. Đảm bảo tính nhất quán của dữ liệu trả về.<br>- Giám sát quá trình Frontend gọi API, hỗ trợ giải thích cấu trúc JSON. (Không phát sinh lỗi logic). |
| 5 | **Huỳnh Trọng Duy**<br>*(Backend Developer)* | - Phát triển API `POST /orders` xử lý dữ liệu giỏ hàng.<br>- Tích hợp cổng thanh toán giả lập (Mock Payment Gateway). | - API xử lý đơn hàng hoạt động ổn định khi nhận tải thực tế từ Client.<br>- Hỗ trợ nhóm Frontend map đúng các trường dữ liệu (Payload mapping) khi thực hiện checkout. (Không cần sửa đổi code Backend). |
| 6 | **Nguyễn Trương Hải Hà**<br>*(Backend Developer)* | - Thiết kế Cỗ máy trạng thái (Order State Machine) cho vòng đời đơn hàng (PENDING -> PAID/FAILED).<br>- Cài đặt thuật toán Idempotency chống thanh toán trùng lặp. | - Logic xử lý trạng thái và tính năng chống trùng lặp hoạt động hoàn hảo trong quá trình System Validation.<br>- Cấu trúc code đáp ứng tốt các yêu cầu phi chức năng (Non-functional requirements) về độ tin cậy (Reliability). |

## 📌 Tổng kết quá trình Tích hợp (Integration Summary)

Việc áp dụng chiến lược phát triển song song (Parallel Development) giúp nhóm tối ưu thời gian. Trong Giai đoạn 2, đội Backend đã chứng minh được chất lượng code (Code Quality) rất tốt khi không phát sinh lỗi logic cốt lõi. Sự chủ động **Refactoring** và khả năng xử lý rủi ro bảo mật của đội Frontend, cùng với việc tự động hóa hạ tầng (Docker) của Scrum Master, đã giúp hệ thống đạt trạng thái "Potentially Shippable" (có thể bàn giao) đúng thời hạn.
